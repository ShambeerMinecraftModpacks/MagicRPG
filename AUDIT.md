# Аудит MagicRPG 2.1.6 и исправления 2.1.7

Дата проверки: 29 августа 2026 года.

## Статус исправлений на 30 августа 2026 года

Все безопасные изменения уровня репозитория из этого отчёта применены:

- устранены все 28 найденных коллизий potion ID и коллизия biome ID 105;
- путь NotEnoughIDs исправлен, а сломанные Git conflict markers в `modpack-metadata.json` удалены;
- Forestry и Tinkers' Construct больше не генерируют медь и олово, рудные кусты сохранены;
- отключены `removeErroringEntities`, сортировка рецептов Forge, статический LAN-порт и объединение offline-профилей;
- сетевые лимиты снижены до 32 МБ, Forge/ServerUtilities chunk-loading лимиты ограничены;
- Wizardry заменён на 1.1.5, установлен TX Loader 1.8.11;
- namespace и имя локали resource pack исправлены, 113 повторных ключей удалены, 68 некорректных строк обезврежены;
- удалены неиспользуемые примеры ProjectE/MineTweaker, старый `perms.txt` заменён инвентаризацией фактических JAR;
- runtime/cache/персональные файлы удалены из Git index, но сохранены локально;
- добавлены официальный защитный Log4j XML Mojang и клиентский JVM-параметр; серверные скрипты, online mode, whitelist и инструкции вынесены отдельно в `server-pack/`;
- настройки клиента сохранены; FPS ограничен 120 и включён VSync.

Статическая повторная проверка после изменений: 99 распознанных эффектов без повторяющихся ID, 34 биома без повторяющихся ID, 85 UTF-8 `.lang` без повторных ключей и некорректных строк, 104/104 JAR присутствуют в клиентском экспорте, отсутствующих путей экспорта нет. Серверные шаблоны вынесены из клиента в `server-pack/`. Тестовый серверный ZIP содержит 396 файловых записей, не содержит клиентских JAR и имеет SHA-256 `EBE5EE3F94A61FF10946FA4A6F2DF50DC635A5A5339A71B0A5853BC3CD79B4A3`.

Не выполнялись действия, которые нельзя безопасно сделать только изменением репозитория:

1. Сессию Ely.by должен завершить владелец аккаунта и затем войти заново.
2. GTNH-моды не обновлялись вслепую. Этот же аудит предупреждает, что версии из таблицы не гарантируют совместимость с MagicRPG; для обновления нужен отдельный согласованный snapshot и полноценный runtime-тест.
3. Существующий мир отсутствует в репозитории, поэтому миграция его NBT/биомов и проверка переходов не выполнялись. Инструкция добавлена в `MIGRATION.md`.
4. EULA Mojang не принимается автоматически. Полный запуск dedicated server возможен только после решения владельца сервера.

## Краткий вывод

Сборка запускается, но сейчас её нельзя считать чистой и безопасно подготовленной к публикации или выделенному серверу. Найдены три проблемы, способные реально ломать игровой процесс или экспорт:

1. 28 подтверждённых коллизий ID эффектов зелий.
2. Коллизия ID биома 105 между DivineRPG и EvilCraft.
3. Метаданные экспорта ссылаются на несуществующий `mods/0-notenoughIDs-2.1.11.jar`, тогда как реальный файл называется `mods/notenoughIDs-2.1.11.jar`.

Также найдены тройная генерация меди и олова, устаревший и рассинхронизированный набор GTNH-модов, слишком широкие сетевые и chunk-loading лимиты, ошибки локализации, 47,74 МБ отслеживаемого Git мусора и неподтверждённая защита старого клиента от Log4Shell. Найденные проблемы звуков исправлены 30 августа 2026 года.

Аудит статический: проверены файлы сборки и предоставленный игровой лог. Полный прогон новой и существующей карты на клиенте и выделенном сервере не выполнялся, поэтому отсутствие других runtime-конфликтов не гарантируется.

## Критические проблемы

### 1. Коллизии ID зелий

Найдено не 1–2, а минимум 28 занятых двумя модами ID. При регистрации один мод перезаписывает эффект другого. Последствия: неправильные эффекты, исчезновение эффектов, рассинхронизация клиента и сервера, ошибки при загрузке сущностей и игроков с сохранёнными эффектами.

| ID | Первый эффект | Второй эффект |
|---:|---|---|
| 31–32 | ThaumicExploration | Electroblob's Wizardry |
| 71 | Forbidden Magic: Dragonwrack | Witchery: Floating |
| 86–89 | Thaumic Tinkerer: Air/Earth/Fire/Water | Witchery: Colorful/Ender Inhibition/Ill Fitting/Volatility |
| 93–96 | Botania: Emptiness/Bloodthirst/Allure/Clear | Aura Cascade: Red/Orange/Yellow/Green |
| 97–98 | Aura Cascade: Blue/Violet | Witchery: Mortal Coil/Absorb Magic |
| 100–111 | Blood Magic (`AWWayofTime`) | 12 эффектов Witchery |
| 115–116 | Blood Magic: Demon Cloak/Amphibian | Sanguimancy: Add Heart/Remove Heart |
| 121 | Blood Arsenal: Bleeding | EvilCraft: Paling |

Основные файлы: `config/AWWayofTime.cfg`, `config/aura.cfg`, `config/BloodArsenal.cfg`, `config/Botania.cfg`, `config/evilcraft.cfg`, `config/ForbiddenMagic.cfg`, `config/Sanguimancy.cfg`, `config/ThaumicExploration.cfg`, `config/ThaumicTinkerer.cfg`, `config/witchery.cfg`, `config/wizardry.cfg`.

`ExtendedPotions` действительно расширяет массив до 4096, но не устраняет повторное назначение одного ID. Его [официальная страница](https://www.curseforge.com/minecraft/mc-mods/extended-potions) подтверждает только расширение доступного диапазона. Код Witchery отдельно предупреждает о перезаписи занятого слота и о сетевых проблемах Witchery-эффектов выше 127: [WitcheryPotions.java](https://github.com/Bogdan-G/Witchery/blob/master/src/main/java/com/emoniph/witchery/brewing/potions/WitcheryPotions.java).

Что делать:

1. Сохранить диапазон Witchery ниже 128.
2. Выделить каждому другому моду собственный непересекающийся диапазон, преимущественно выше 127.
3. Не копировать номера наугад: сначала составить окончательную карту всех эффектов после согласованного обновления модов.
4. Проверить подключение к выделенному серверу, применение каждого перенесённого эффекта и повторный вход.
5. Перед открытием существующего мира сделать резервную копию и очистить временные эффекты у игроков/сущностей либо выполнить миграцию NBT.

Текущий GTNH сам использует ID выше 127 для некоторых модов, например [ThaumicHorizons 135–139](https://github.com/GTNewHorizons/GT-New-Horizons-Modpack/blob/master/config/ThaumicHorizons.cfg), но это не означает, что любой старый мод автоматически корректно синхронизирует такие ID.

### 2. Коллизия ID биома 105

- `config/DivineRPG.cfg`: `Vethea biome ID=105`.
- `config/evilcraft.cfg`: `biomeDegraded=105`.

Это может подменять биом, его декорацию, спавны и генерацию. Остальные найденные ID биомов и измерений между собой не пересекаются; подтверждённых коллизий ID зачарований нет.

Просто поменять число в существующей карте нельзя: ID биома хранится в чанках. После изменения старые чанки могут интерпретироваться как другой биом. Для новой карты нужно назначить свободный ID. Для существующей — сначала резервная копия, затем осознанная миграция биомов или сохранение ID того мода, чьи чанки уже важнее.

### 3. Экспорт может потерять NotEnoughIDs

В `modpack-metadata.json` указан `mods/0-notenoughIDs-2.1.11.jar`, которого нет. Реальный файл — `mods/notenoughIDs-2.1.11.jar`. Тот же несуществующий путь используется в `filesEnvironments`.

Результат: экспортёр может пропустить реальный NotEnoughIDs или остановить строгий экспорт. Для этой сборки это особенно опасно: удаление NEID из уже созданного мира способно привести к неверным block/item ID и порче карты.

Нужно заменить путь в обеих секциях метаданных и проверить чистую установку из каждого формата экспорта: CurseForge, Modrinth и offline.

### 4. Токен авторизации раскрыт в предоставленном логе

Лог содержит полный bearer/access token Ely.by. Его нельзя считать секретным после передачи или публикации лога. Токен в репозитории не найден, но учётную сессию следует завершить и войти заново, чтобы старый токен перестал работать. Сам токен в этот отчёт намеренно не скопирован.

### 5. Защита старого клиента от Log4Shell не подтверждена

Официальный манифест Forge/FML 1.7.10 содержит Log4j `2.0-beta9`: [FML 1.7.10 manifest](https://github.com/MinecraftForge/FML/blob/master/jsons/1.7.10.json). В сборке нет серверных стартовых скриптов, специального `log4j2_17-111.xml` и JVM-параметра, который подтверждал бы применение исправленной конфигурации. X Minecraft Launcher может иметь собственную защиту, но по содержимому сборки это установить нельзя.

Mojang отдельно предупреждает, что сторонние и модифицированные клиенты могли не получить автоматическое исправление, и для серверов 1.7–1.11.2 публикует специальную конфигурацию: [официальное сообщение Minecraft](https://www.minecraft.net/fr-fr/article/important-message--security-vulnerability-java-edition).

До проверки фактической команды запуска клиент и сервер следует считать потенциально незащищёнными. В логе также виден Java `1.8.0_51`, а `instance.json` не закрепляет нужный Java runtime.

## Высокий приоритет

### 6. Медь и олово генерируются сразу тремя модами

В новых чанках одновременно включены:

- Thermal Foundation: `copper`, `copperHigh` и `tin` в `config/cofh/world/ThermalFoundation-Ores.json`.
- Forestry: `ore.copper=true`, `ore.tin=true`.
- Tinkers' Construct: `Generate Copper=true`, `Generate Surface Copper=true`, `Generate Tin=true`, `Generate Surface Tin=true`.

Только Thermal Foundation пытается создать 18 медных и 8 оловянных кластеров на чанк до учёта двух остальных модов. Это не технический дубль одного блока, а завышенная экономика ресурсов и лишняя нагрузка генерации мира.

Рекомендуется оставить один основной источник, вероятнее Thermal Foundation, а в Forestry и Tinkers' Construct выключить медь/олово. Рудные кусты можно оставить отдельно, если они нужны прогрессии. Изменение повлияет только на новые чанки; уже созданные руды останутся.

### 8. Серверная часть фактически не оформлена

README обещает `start.bat` и `start.sh`, но в репозитории нет стартовых скриптов, `server.properties`, `eula.txt` или отдельного серверного состава. `emittedServerFiles` пуст.

`filesEnvironments` заполнен лишь для 19 путей. Вероятные клиентские моды `Controlling`, `DefaultKeys`, `MouseTweaks`, `SmoothFont` и `TiCTooltips` не имеют явной пометки `server: unsupported`. JourneyMap помечен как optional вместо unsupported, а UniMixins — optional на обеих сторонах, хотя от него зависят mixin-моды. Автоматически собранный серверный архив поэтому нельзя считать проверенным.

### 9. Опасные защитные настройки Forge

- `removeErroringEntities=true` удаляет сущность, на которой произошла ошибка. Это повышает живучесть сервера, но может молча удалить питомца, босса, вагонетку или другую ценную сущность и скрыть причину дефекта. Комментарий «Безопасно» неверен.
- `removeErroringTileEntities=false` выставлен правильно: механизмы и их содержимое не удаляются автоматически.
- `sortRecipies=true` включён при предупреждении самого Forge о возможной десинхронизации конфликтующих рецептов. При наличии MineTweaker это нужно отдельно проверить или отключить.
- README утверждает, что включено удаление «багованных блоков», хотя удаление TileEntity выключено. Описание не соответствует конфигу.

### 10. Слишком широкие сетевые и chunk-loading лимиты

В `config/hodgepodge.cfg` разрешены входящие NBT и пакеты размером до 268 435 456 байт каждый, то есть 256 МБ. Для публичного сервера это увеличивает риск исчерпания памяти или длительной обработки пакета недоверенным клиентом. Реалистичный лимит для тяжёлой модовой сборки следует подобрать тестом, обычно начиная с 16–32 МБ, а не сразу возвращаться к ванильным 2 МБ.

В `config/forgeChunkLoading.cfg` для `serverutilities` стоят миллион чанков на ticket и миллион tickets. Ранги ServerUtilities дополнительно разрешают 50 загруженных чанков обычному игроку, 100 VIP и 1000 admin. Ранговые ограничения сейчас спасают от худшего сценария, но Forge не задаёт разумного последнего предела. Значения нужно согласовать с реальным количеством игроков и RAM сервера.

### 11. Offline/LAN-конфигурация требует осторожности

`enableDefaultLanPort=true`, порт фиксирован на `25565`. В логе сервер не смог подтвердить имя игрока, но всё равно пустил его, а `merge_offline_mode_players=TRUE` объединяет offline-профили. Для домашней LAN это может быть осознанным выбором. Для публичного сервера нужны `online-mode=true`, закрытый firewall до настройки, отсутствие проброса LAN-порта и проверка UUID/рангов.

Aurora Webserver выключен (`enable=false`), поэтому его публичные страницы сейчас не открыты. Если его включить, страницы списка игроков, модов, команд и информации о мире нельзя оставлять в режиме `ENABLED` без аутентификации.

## Производительность и стабильность

### Предоставленный лог

- 886 предупреждений, из них 874 — отсутствующие звуковые файлы.
- 1 строка ERROR — пойманная ошибка EntityTracker.
- 3 сообщения `Can't keep up`: отставание 2,6–4,2 секунды.
- Ошибка EntityTracker в 17:57:48 была поймана, после неё игра продолжала работать почти 55 минут. Это не финальный краш процесса.
- Лог обрывается на `AL lib: (EE) alc_cleanup: 1 device not closed` без Java stack trace, fatal-сообщения или exit code. По этому файлу точную причину окончательного завершения доказать нельзя.

Два поздних зависания произошли в 18:22:54 и 18:52:58 — почти ровно через 30 минут. ServerUtilities тоже запускает backup каждые `0.5` часа. Это сильная корреляция с дисковым I/O резервного копирования, но в логе нет прямой строки старта backup, поэтому это гипотеза, а не доказанный источник. Резервные копии включены разумно: threaded, compression 1, 12 копий, только при игроках онлайн.

### Память и JVM

- README рекомендует 4096–6144 МБ, но `instance.json` задаёт `minMemory=256`, `maxMemory=6144`. Маленький начальный heap допускает лишние расширения памяти и не соответствует документации.
- JVM-флаги README агрессивны для Java 8u51: `MaxGCPauseMillis=50`, 50–80% young generation и экспериментальные G1-параметры. Без сравнительных замеров это не «идеальные» параметры.
- Если оставаться на Java 8, следует закрепить актуальную поддерживаемую 64-битную сборку Java 8 и использовать более простой профиль GC. Альтернатива — отдельный проект миграции на [GTNH lwjgl3ify и Java 17+](https://github.com/GTNewHorizons/lwjgl3ify); это не замена Java одним переключателем и требует согласованного обновления зависимостей.

### Клиентские настройки

- Angelica настроена в целом разумно: VAO, multidraw, culling, threaded chunk building, 3 worker-потока.
- Dynamic Lights включён; на слабых CPU/GPU он может быть заметной статьёй нагрузки.
- В `options.txt` стоит `maxFps=185` при отключённых VSync и fullscreen. Это персональная настройка, которая может зря держать GPU под высокой нагрузкой.
- `renderDistance=8` и mipmap 4 сами по себе не выглядят чрезмерными.

## Ресурсы и локализация

### Отсутствующие звуки

В исходном логе было 874 предупреждения о недостающих звуках, 167 уникальных путей:

### Сломанный namespace ресурспака

Папка `assets/alchemicalwizardryBooks` содержит заглавную букву. Minecraft игнорирует этот namespace, что восемь раз отражено в логе. В JAR Blood Magic корректное имя — `assets/alchemicalwizardrybooks`. Папку нужно переименовать в полностью строчную.

`assets/ae2wct/lang/ru_ru.lang` имеет неправильный регистр имени локали. На Windows это может случайно работать, но после упаковки или на case-sensitive файловой системе файл может не загрузиться; ожидается `ru_RU.lang`.

### Качество `.lang`

Статическая проверка 85 файлов локализации нашла:

- 53 повторных ключа с разными переводами; последнее значение молча побеждает.
- 60 повторных ключей с одинаковым значением.

Больше всего конфликтующих повторов: TConstruct — 20, ExtraTiC — 14, Botania — 6, Twilight Forest — 5. Часть строк без `=` является декоративными заголовками, но есть и реальные обломки: `primus`, неключевые русские строки и многострочный ASCII-текст Blood Arsenal.

## Уже исправленная ошибка EntityTracker

Ранее в `config/enderio/EnderIO.cfg` было включено экспериментальное `replaceWitherSkeletons=true`. Оно заменено на `false`. Это соответствует стеку ошибки при переносе сущности между измерениями и убирает наиболее вероятный триггер повторной регистрации сущности.

Важно: предоставленный файл не доказывает финальный краш. Исключение `Entity is already tracked!` было поймано сервером, и игра продолжила работу. Для точного разбора окончательного завершения нужен полный `latest.log`, `crash-reports/...` либо exit code лаунчера.
